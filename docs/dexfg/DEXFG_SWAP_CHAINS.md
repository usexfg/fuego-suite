# DeXFG Swap Chains

XFG is one side of every DeXFG swap. The counterparty chains come from one table:
`src/SwapDaemon/SwapPairCatalog.h`, an append-only X-macro catalog of wire ids. Ids are
serialized in swap records and on the wire; they are never renumbered or reused.

## When a pair can start a swap

All four gates must pass:

1. **Catalog support is ACTIVE or ADAPTER** (`isExecutableSwapPair`, which the relay's
   `isExecutablePair` returns). GATED pairs have a client but no passed end-to-end gate:
   BTC, LTC and BCH have a full-node path (lock check with `gettxout`, claim discovery by
   block scan) that still needs the regtest two-daemon run (remediation plan 1.9); the
   other UTXO pairs and XMR follow. STAGED ids are reserved only.
2. **Swap records and the order book carry the id** (`isProtocolSwapPair`: everything but
   STAGED).
3. **The chain client is ready**: a signer, an RPC whose chain id matches the catalog, and
   a contract deployed on that chain — `HashedTimelock` for EVM (readiness probes its
   on-chain code), the HTLC program for Solana.
4. **A live price quote allows it** (`validateNewSwapRate`). A settlement asset with no
   verified feed id is `UNPRICED` and fails closed.

ACTIVE means a dedicated client class; ADAPTER means the generic `EthChainClient`
registered from an `evm_chains` config entry. Both are executable. Every EVM pair settles
in its chain's native coin: `HashedTimelock.lock()` is `payable` and takes no token, so
Rootstock settles in RBTC and Gnosis in xDAI.

## Configuring an EVM pair

`evm_chains` is the only EVM config path. The flat `eth_*`, `arb_*`, … fields are retired
and the loader refuses a config that carries one, naming the `evm_chains` key to use.
`swap_config.example.json` has an entry for every executable EVM pair except GLEEC and
Robinhood Chain, which ship no public endpoint; `test_example_evm_chains_cover_every_adapter_pair`
fails if that block drifts from the catalog. An entry needs `rpc_url`, a funded
`private_key` with its `address`, and on mainnet a `chain_id` equal to the catalog value.

Both timelock registries are pinned. `contracts/artifacts-build` compiles them with solc
0.8.34 (optimizer, 200 runs, EVM `paris`); CI fails if the committed artifacts differ from
a fresh build.

| Contract | Runtime code keccak-256 | Canonical address |
|---|---|---|
| `HashedTimelock` (hash locks) | `8dfdda4b…ecb68` | `0xcef71d1a85d98f0d9ce242b41bbd9fd5d99aefeb` |
| `PointTimelock` (point locks, F33) | `f6efcc40…f661b` | `0x10e9f7e464f3e538b9324fb830c2d8daaf7126da` |

- Readiness requires the HTLC registry's runtime code to hash to the pinned value. Any other
  contract at the address, including another build of the same source, reports not ready.
- Point locks are offered on a chain only when the PointTimelock registry holds the pinned
  code. With no code there, the chain keeps hash locks. Other code there, or an unreachable
  RPC, blocks new swaps on the chain instead of falling back to a hash lock.
- Without `htlc_registry` / `ptlc_registry`, the canonical addresses apply: the committed
  artifacts deployed with a zero salt through the deterministic deployment proxy
  `0x4e59b44847b379578588920ca78fbf26c0b4956c`. `xfg-swapd --print-htlc-deployment <.bin>`
  prints the transaction (`to`, `data`) that deploys either contract. The proxy must exist
  on the chain; check with `eth_getCode` first.
- zkSync Era and Abstract (EraVM) derive CREATE2 addresses and compile bytecode
  differently: they get no default and need `htlc_registry` plus `htlc_registry_code_hash`.
  They have no point locks.

## Price feeds

`src/SwapDaemon/AssetCatalog.cpp` maps each settlement asset to a `coingecko:*` id.
xfg-swapd's price worker reads that id from DeFiLlama (primary) and CoinGecko (secondary).

- **PEAQ**: priced from `coingecko:peaq-2`. DeFiLlama returns symbol PEAQ for it, and CoinGecko's
  `peaq-2` names homepage peaq.xyz and asset platform peaq, the native token of chain 3338
  (`scripts/probe-feed-ids.py`, run in CI on 2026-11-07). `coingecko:peaq` and
  `coingecko:peaq-network` do not exist.
- **GLEEC**: no feed id. `coingecko:gleec-coin` resolves on neither DeFiLlama nor CoinGecko, and no
  source ties the GLEEC coin to the native coin of the GLEEC EVM chain (11169). GLEEC quotes are
  `UNPRICED` and every new GLEEC swap is refused.

## Not in the catalog: Tempo

Tempo (chain id 4217) has no native coin; `eth_getBalance` returns a constant. With nothing
native to escrow, `HashedTimelock` cannot lock value there. Supporting Tempo needs a
token-escrow HTLC contract, a token lock/claim/refund path in `EthRpcClient`, a chosen
settlement token with a verified price feed, and a new catalog id. Fuego Valise lists Tempo
in its ERC20 wallet layer only.

## Fuego Valise mirror

The wallet mirrors the catalog in `SwapPairSdk` (39 ids: every id except SIA, DOGE, DASH,
ZEC, ZANO, TON and DOT) and in `chains.yaml`, where all 32 catalog EVM chains are
`tier: swap` and Tempo is `tier: wallet`. The Cross-Chain tab lists chains from xfg-swapd's
own readiness report, so a pair appears there only when the daemon carries it.
