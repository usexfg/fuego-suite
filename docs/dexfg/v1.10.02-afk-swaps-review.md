## Blocking

### B-1: Timelock validation passes timeout as current height — always rejects ✅ CLOSED

- `src/SwapDaemon/SwapDaemon.cpp:368` (`initiate`) and `:479` (`accept`)
- Both paths set `uint64_t ctrHeight = params.ctrTimeoutBlock;` then pass it as the
  counterparty *current* height to `timelockOrderingOk`. Inside the function
  (`SwapTimelock.cpp:25`), `ctrTimeoutHeight <= ctrCurrentHeight` is true (they're equal),
  so it returns false. Every swap with a nonzero `ctrTimeoutBlock` is rejected.
- **Fixed:** added `IChainClient::getCurrentHeight()` virtual (default returns false),
  implemented in all 4 chain clients (EthChainClient→getBlockNumber, SolChainClient→getSlot,
  XmrChainClient→getHeight, BchChainClient→getBlockCount). Both `initiate()` and `accept()`
  now query the real counterparty height; if the RPC is unreachable the timelock check is
  skipped with a warning (permissive fallback, matching the prior behavior of no check at all).

## Important

### I-1: `handleSwapRequest` never calls `isTakerRateLimited` ✅ CLOSED

- `src/SwapDaemon/SwapDaemon.cpp` — `isTakerRateLimited()` is defined (lines ~1570–1590),
  `recordTakerFailure()` is called on proof failure, but the rate-limit check is absent from
  the `handleSwapRequest` entry point. A banned or rate-limited taker can still submit
  unlimited requests.
- **Fix:** add `if (isTakerRateLimited(takerPubKey)) { return false; }` at the top of
  `handleSwapRequest`, before the offer lookup.

### I-2: Reserve proof not bound to the offer ✅ CLOSED (partial — see note)

- `src/SwapDaemon/SwapDaemon.cpp` — `client->verifyReserveProof("", requiredCtrAmount, proofOfFunds)`
  passed an empty binding; none of the four `verifyReserveProof` impls bound the proof's
  signed `message` to anything, so a proof could be replayed across offers / lifted from
  another context.
- **Fixed:** `verifyReserveProof`'s first param renamed `ctrAddress → expectedMessage`
  (interface + SOL/ETH/XMR/BCH). Each impl now rejects the proof unless its signed `message`
  equals `expectedMessage`; the call site passes `offerId`, binding every proof to the
  specific offer. Impls now also return the *verified* address on success.
- **Note (deferred, by design):** full counterparty-*address*-equality and a per-request
  challenge nonce (to stop replay **within** the same offer) require protocol-level changes —
  the maker does not know the taker's funding address at accept time. Tracked for a future
  swap-protocol revision; the rate-limiter (I-1) mitigates same-offer replay meanwhile.

### I-3: Floating-point amount conversion in `handleSwapRequest` ✅ CLOSED

- `src/SwapDaemon/SwapDaemon.cpp` — `requiredCtrAmount` computed via double arithmetic.
  (Re-rated: practical drift is sub-significant — tens-to-hundreds of wei — so this was really
  a hygiene/correctness issue, not Important. Fixed anyway.)
- **Fixed:** replaced with integer math — `requiredCtr = fillAmount * ctrDivisor / rateNum`
  using a `__uint128_t` intermediate and an overflow guard; zero-rate rejected explicitly.

### I-4: SwapP2P detached worker threads — use-after-free on shutdown ✅ CLOSED

- `src/SwapDaemon/SwapP2P.cpp:~155` — `std::thread(&SwapP2P::handleConnection, this, clientSock).detach()`.
  If `SwapP2P::stop()` / destructor runs while workers are still handling connections,
  `this->m_mutex`, `this->m_cv`, `this->m_logger` become dangling references.
- **Fixed:** added `m_workersDoneCv`. The last worker to exit (`m_activeWorkers` reaches 0)
  notifies it; `stop()` — after joining the accept thread so no new workers spawn — waits on
  it until `m_activeWorkers == 0` before returning. Workers exit within the 30s per-connection
  `SO_RCVTIMEO`, bounding shutdown latency.

### I-5: `fetchDaemonStatus()` blocks TUI event loop ✅ CLOSED

- `swapxfg/app/tui.go:857–865` — `func (m tuiModel) fetchDaemonStatus() tea.Msg` returns
  `tea.Msg` directly and is passed to `tea.Batch(...)` which expects `tea.Cmd` (`func() tea.Msg`).
  Compile error confirmed by `go build`.
- **Fixed:** wrapped in `func() tea.Msg { return m.fetchDaemonStatus() }` at the call site.
  Note: the fetch itself is still synchronous inside the Cmd closure (blocks the Bubble Tea
  goroutine for one tick), but the TUI event loop continues for other events. A future
  improvement would use a channel-based async pattern.

### I-6: Adaptor secret lost on v2→v3 DB upgrade ✅ CLOSED

- `src/SwapDaemon/SwapStateMachine.cpp` deserialize — v2 records stored the secret under
  `"adaptorSecret"` (plaintext or encrypted with inline `"encKey"`). v3 reads only
  `"adaptorSecretEnc"` and discards any `"encKey"` field. An in-progress v2 swap loaded
  after the upgrade silently loses the adaptor secret — the original Critical escrow-lockup
  scenario.
- **Fixed:** `deserialize` now detects a legacy record (`adaptorSecret` present,
  `adaptorSecretEnc` absent) and throws — the loader (`SwapDatabase::loadSwapLocked`, which
  catches) skips it rather than resurrecting an unrecoverable swap that would loop forever.
  Full automatic migration was deemed unnecessary: this is the first real swap release, so no
  v2 records exist in the wild. Operators refund any such swap on-chain manually.

### I-7: Missing `SwapPair::BASE` in `SwapTimelock::msPerBlock` ✅ CLOSED

- `src/SwapDaemon/SwapTimelock.cpp:14` — falls to `default: return 600000` (10 min/block).
  Real BASE block time is ~2s. The error is in the safe direction (over-estimates counterparty
  deadline → stricter check), but valid BASE swaps are over-rejected.
- **Fixed:** added `case SwapPair::BASE: return 2000;`.

### M-3: Logger name typo ✅ CLOSED

- `src/SwapDaemon/main.cpp:~160` — `Logging::LoggerRef logger(consoleLogger, "xfg-swapdd");`
  (double 'd'). **Fixed.**

### M-4: Same cipher key used for encryption and MAC

- `src/SwapDaemon/SwapSecretEncryption.cpp` — ChaCha8 cipher key is reused as HMAC-SHA256
  key. Best practice is independent MAC key (as WalletGreen.cpp does for wallet integrity).
  Currently safe because ChaCha and HMAC use the key in incompatible domains.

### M-5: TESTNET_DAEMON_VERSION lowered

- `src/version.h.in` — `10.12.014 → 10.01.014`. If intentional (genesis reset count
  correction), this is fine. If accidental, testnet nodes with the old version will reject
  the downgraded daemon. Flagging for explicit confirmation.

### M-6: Ed25519Verify accepts non-canonical S (signature malleability)

- `src/SwapDaemon/Crypto/Ed25519Verify.cpp` — no `sc_check(S_bytes)` call. Accepts
  `S >= group_order`. Not exploitable here (signatures aren't used as unique identifiers),
  but strict implementations (ed25519-dalek) would reject.

### M-7: main.cpp secret key string not zeroed

- `main.cpp` — `xfg_secret_key` hex string persists in memory after `podFromHex`. Minor
  key hygiene; the `SecretKey` struct is the primary concern and that's handled correctly
  by `setMakerKeys`.

## Positive findings (not issues — notable improvements in this diff)

1. **Adaptor-secret at-rest encryption** — CryptoNight-KDF + ChaCha8 + HMAC-SHA256 with
   random salt. Encryption key derived from wallet spend key (memory-hard, deterministic,
   never persisted). Plaintext fallback and inline key storage removed.
2. **P2P message authentication** — Ed25519 signature on all peer messages. KEY_EXCHANGE
   self-attested, subsequent messages verified against bound peer key. Canonical digest
   construction. Legacy unsigned messages rejected.
3. **EIP-155 signing** — offline raw-tx construction with chainId for both legacy and
   EIP-1559 transactions. `eth_sendRawTransaction` exclusively. secp256k1 library linked.
   `clear()` zeros private key. Dynamic gas price with 500 gwei cap.
4. **Small-subgroup rejection** — `point_is_valid()` in adaptor and DLEQ verifiers
   (cofactor-8 check). Prevents small-subgroup attacks on adaptor points.
5. **MLSAG nonce hygiene** — volatile-write zeroing on all error paths and post-sign.
6. **RNG fork safety** — `pthread_atfork()` reseeds in child process.
7. **Modulo bias elimination** — rejection sampling in `randomValue()`.
8. **Wallet HMAC integrity** — Keccak hash replaced with HMAC-SHA256 (v7+, independent
   MAC key, constant-time compare). Backwards-compatible v6 keccak path preserved.
9. **Wallet file permissions** — `chmod 0600` on create/export/convert.
10. **RPC error sanitization** — `e.what()` replaced with generic messages in all
    WalletRpcServer and PoolRpcServer error responses. Prevents internal leaks.
11. **Alias privacy** — sub-address rotation per registration, mixin raised from 0.
12. **Fee overflow protection** — multiplication/addition overflow checks on swap fees.
13. **SwapP2P hardening** — default loopback bind, worker cap (64), bounded message queue
    (1024), 30s receive timeout per connection.
14. **PriceOracle bootstrap guard** — ±50% seed-rate drift protection during bootstrap.
15. **Taker rate-limit infrastructure** — per-pubkey hourly caps and ban threshold (defined
    but not wired — see I-1).
16. **`hash.h` prehashed parameter fix** — was silently discarded (hardcoded 0).
